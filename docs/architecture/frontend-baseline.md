## Captured mock browser baseline

With `VITE_USE_MOCK_DATA=true`, task-owned Chromium 151 collected 748 route and viewport observations: all 17 router entries, all 22 required viewport rows, both themes and the source-derived readiness selector for each route. The collector persisted a partial JSON report after every observation, then a final report and 170 representative screenshots under Playwright's ignored `test-results/` output. No route collection error or horizontal-overflow observation was recorded in this Chromium mock run.

The approved digest-pinned Playwright 1.62.1 Noble container was exercised with no network, mounts or published ports, `pwuser`, dropped capabilities and `no-new-privileges`. It used Node 24.20.0 and a disposable frontend snapshot with copied locked dependencies. Run 210 reran the eight representative Chromium/Firefox states from the exact current harness blob `34481127bb33b26e5adb61ea02b36d1695ac6f84`, retaining an unmodified report for every state. Five reached `stage: axe` with `keyboardFocusCount: 1`; Firefox light 390x844 and light 1440x900 each retain one serious-or-critical axe finding. Chromium dark 1440x900 stopped at `stage: navigation` with `Target crashed`, and Firefox dark 390x844 reached `stage: axe` but recorded `keyboardFocusCount: 0`; both are baseline failures, not coverage passes. The first two-worker invocation exited 1 after Firefox 390x844 browser thread/PID failures before its test bodies; the two missing Firefox states were then run once with one worker, exit 0, without changing the test timeout, selector or assertion. Run 205 exercised WebKit with the same bounded runtime: each dark/light 390x844 and 1440x900 observation persisted `stage: readiness` and `locator.count: Test timeout of 60000ms exceeded.` before keyboard, accessibility-tree or axe. Their separate reports and nonempty Playwright traces are baseline failures, not coverage passes.

The full Chromium matrix retained from the unchanged route-audit harness records 1168 hit-test, 608 overlap and 270 undersized-target findings across 748 observations. Chromium recorded four serious or critical axe results in representative observations. These are baseline defects captured by `tests/audit/interactionAudit.ts`, not accepted interaction results. The empty exception document did not suppress them. The final evidence archive includes current Chromium and Firefox a11y outputs, current WebKit stage reports/traces and the prior complete Chromium matrix/screenshots.

## Source-backed findings

- 15 router paths are statically found. Existing fetch guards preserve cookie credentials and `X-Requested-With`; production API calls are centralized only partly because router and other code still call `fetch` directly.
- The frontend API inventory and 205 parsed backend route declarations are in `frontend-inventory.json`. API and media contract changes are prohibited in this slice.
- `useWebSocket.ts` is the main singleton owner, but `useProxySettings.ts` creates another WebSocket. This is a later ownership finding.
- Native `alert` and `confirm`, non-semantic click surfaces, `any`, direct DOM writes, listener/timer sites, `transition: all`, raw `100vh`, candidate undersize dimensions, PWA and player references are enumerated in the JSON inventory.
- VitePWA owns generated output, while `public/manifest.json` remains an inventory item. `vite.config.ts` has `orientation: 'portrait-primary'`; no production configuration was changed in P0/P1.
